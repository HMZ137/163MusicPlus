# 均衡器增强方案（2026-11-28 · 待需求方敲定）

> 现状基线：`util/EqualizerController.java` + `activity/EqualizerActivity.java`
> - 走系统 `android.media.audiofx.Equalizer`，不自写 DSP（手表 CPU 有限，系统音效在音频链路里跑更省）
> - 只暴露 **3 个可调段**（低 60Hz / 中 1kHz / 高 12kHz），映射到设备实际段（通常 5 段）的 `0 / bands/2 / bands-1`
> - 8 个内置预设 + 自定义，增益 ±12dB，步进调节
> - 挂在播放器的 audioSession 上，切引擎/切歌后重新 attach
> - 已知限制：**它只作用于本 App 的播放输出**，不影响系统其他声音；蓝牙耳机同样生效（走同一 session）

---

## 方案 A｜把现有三段做「真·多段」（改动最小，风险最低）

**界面形态**：竖排在手表上是一条条横条（每段一行：频率 + 当前 dB + 左右步进），与现在的三段行完全同构，只是行数从 3 行变成设备的 5 行（读 `getNumberOfBands()` 动态生成）。

| 增强点 | 说明 |
|---|---|
| 动态段数 | 有几个段就画几行，标签用 `getCenterFreq()` 换算成 Hz/kHz，不再写死 60Hz/1kHz/12kHz |
| 自定义预设 | 现在的「自定义」只是一个状态，不能保存。改成可**存多套**（长按预设名 → 重命名/删除），存 `eq_presets` JSON |
| A/B 旁路 | 长按「均衡器」开关 → 临时 bypass 2 秒，松手恢复（对比调音效果最快的手段） |
| 增益条可视化 | 每行右侧加一条极细的 ±12dB 双向条（自绘，不用 SeekBar），一眼看出调的是哪段 |

- **代价**：`EqualizerController` 小改（把 3 段对外接口扩成 N 段，保留 3 段旧接口做兼容）；`EqualizerActivity` 重写行构建。约 1 个工作日量级。
- **风险**：不同设备段数与频率不同，UI 要能自适应；部分手表 ROM 的 `getNumberOfBands()` 返回 0（已挂不上，保持现状兜底）。

---

## 方案 B｜A + 系统音效叠加（BassBoost / LoudnessEnhancer）★推荐

在方案 A 之上，新增一个「音效」分区（同一页，放在频段下面），每项一行「开关 + 强度」：

| 音效 | 系统类 | 作用 | 默认 |
|---|---|---|---|
| 低音增强 | `BassBoost` | 补 60Hz 以下，EQ 加不出来的那部分 | 关 |
| 响度增强 | `LoudnessEnhancer`（API 19+） | 抬整体响度/小音量下的动态，手表外放很有效 | 关 |
| 环绕 | `Virtualizer` | 空间感（对单声道/小喇叭常常是反效果） | 关，且折叠进「高级」 |

- **代价**：`EqualizerController` 增加 2~3 个 effect 实例的 attach/release + 强度持久化；UI 加 3 行。约 0.5 天。
- **风险**：三个 effect 同时挂同一 session，个别 ROM 会互相打架（表现为无声/爆音）。做法：**同时只允许最多 2 个开启**，或出错时自动全关并提示。
- **为什么推荐**：手表扬声器小、低频弱，「低音增强 + 响度增强」带来的听感提升远大于把 EQ 从 3 段做成 5 段。

## 方案 C｜自研 DSP（不推荐，列出来是为了排除）

在 JVM 侧做 FFT → 分段增益 → IFFT，或自写 IIR 滤波器组。

- **代价**：需要改动播放器输出链路（ExoPlayer 的 `AudioProcessor`），实时处理 44.1kHz 立体声在手表上功耗与发热都不可控；且蓝牙输出走系统混音，自研链路对蓝牙无效。
- **结论**：除需求方明确要「不依赖 ROM 音效」外，不建议。

---

## 建议节奏

1. **第一期**：方案 B 的「低音增强 + 响度增强」两行 + 方案 A 的动态段数（这两个合起来用户体感最明显）
2. **第二期**：自定义预设多套 + A/B 旁路
3. **第三期（可选）**：按输出设备（外放 / 蓝牙）分别记一套参数

## 需要你拍板的点

1. 选 **A / B / C** 哪条路线（推荐 B）
2. 段数：要「设备有几段用几段」（5 段），还是维持「低/中/高」3 段更好按（手表屏幕小，5 行 + 2 个音效行 = 7 行，需要滚动）
3. 自定义预设：要不要支持多套（要的话需要重命名弹窗，交互复杂度上一档）
4. 环绕（Virtualizer）要不要露出来
